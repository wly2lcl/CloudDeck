# 11 开发计划

任务编号：`P<里程碑>-<序号>`。估时为单人日，含自测，不含 review 等待。

## 完成定义（DoD）

任何任务完成必须同时满足：

- [ ] 代码合并主分支，CI 全绿
- [ ] 有对应测试（单元/契约/集成按任务类型）
- [ ] 契约或行为变更已更新文档
- [ ] 可在本地 `pnpm dev` 复现
- [ ] 有可演示路径（接口 curl 或 UI 操作）

## 范围闸门

- M0–M2 不实现平台 key 池、订阅、发票、退款。
- M3 只实现额度与硬上限；账单与发票在 M5。
- 私有化交付不在主线；出现付费意向客户后单独立项。
- 所有能力默认 `credentials.policy: tenant`。

## 排期风险与缓冲

- 每个里程碑预留 20% 缓冲；M3 的 TTS 质量与 GPU 环境是最大不确定项。
- 第三方 CLI 版本变动可能让 M2 延期，P2-03 前先做一天 spike 锁定版本。
- 若只有 1 人，M0–M2 串行约 6–7 周，M3 起建议至少 2 人。

- 每日：站会 10 分钟，只同步阻塞项。
- 每周：周五演示一个可操作路径，不用 PPT。
- 每里程碑：更新 12 风险表，关闭或新增待决策。
