# ADR-0004 资产模型与内容链

- 状态：已接受
- 日期：2026-11-14

## 背景

小说、剧本、有声、视频若各自存文件，无法回答「这个角色设定在哪些产物里被用过」「改一版稿件哪些下游过期」。平台差异化在于跨能力的资产复用，而不是工具数量。

## 决策

- 资产不可变：内容变化即新版本，`assets` 存当前指针，`asset_versions` 存历史。
- 所有资产有明确 `AssetType`，决定可被哪些能力消费、由哪个渲染器展示。
- 派生关系写入 `asset_links`（`derived_from` / `references` / `adapts`），构成内容链。
- 能力之间不直接调用，只能消费上游资产、产出下游资产。
- 客户端以内容链图为主视图，而不是能力列表。

## 后果

正面：
- 可追溯：任一成片可回溯到稿件版本与音色版本
- 可增量：上游变更能定位受影响的下游
- 可复用：设定、角色、音色在项目内只维护一份
- 能力解耦：新增能力只需声明消费/产出类型

代价：
- 需要版本与链路的额外存储与查询（递归 CTE）
- 资产类型枚举会随能力增长，需要治理
- 版本管理对用户体验有要求（diff、回滚、清理）

## 替代方案

- **按 job 存文件**：简单，但无法复用与追溯，等同单点工具。
- **按能力存各自数据库**：短期快，长期形成数据孤岛，正是要避免的。
