# ADR-0001 四层契约作为系统边界

- 状态：已接受
- 日期：2026-11-14

## 背景

平台需要同时支持自研流水线与多个第三方 agent（Claude Code、OpenCode、dsh），且要求能力可插拔、低耦合。若按「模块调用」组织，任何引擎变更都会扩散到业务代码。

## 决策

以四层契约作为唯一耦合点：

1. CapabilityManifest：能力声明（IO、权限、预算、driver 路由）
2. Driver 协议：`submit / events / cancel / collect`
3. JobEvent：统一事件与进度
4. AssetRef / AssetType：跨能力数据流

平台只实现契约，不认识具体引擎；能力只声明契约，不调用彼此。

## 后果

正面：
- 换引擎 = 换 driver，平台与客户端不动
- 能力可以用不同实现混搭（LLM + 流水线 + agent）
- 契约可测试、可版本化、可灰度

代价：
- 早期需要额外设计 schema 与适配层
- 简单能力也要走一遍 manifest，存在仪式感成本
- 契约设计错误会被所有实现放大，必须先用 mock 验证

## 替代方案

- **模块化单体 + 内部接口**：耦合更低成本，但换引擎需改代码，违背可插拔目标。
- **直接采用某个 agent 框架的插件体系（如 dsh/Cordis）**：省事，但把产品命脉绑定到框架版本与内部模型，且该框架不含多租户/资产/计费。
