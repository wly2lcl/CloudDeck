# ADR-0002 引擎一律进程/容器隔离

- 状态：已接受
- 日期：2026-11-14

## 背景

候选引擎技术栈各异（Node CLI、Python worker、Go harness），且都是第三方或独立演进的代码。若在控制面进程内加载，会带来版本冲突、崩溃传染、安全边界缺失。

## 决策

- driver 一律独立进程或独立服务，通过 stdio / HTTP / ACP / 队列交互。
- 每个 job 一个沙箱容器，非 root、只读根、默认无网络。
- 控制面与 runner 禁止 import 任何引擎的内部包或 SDK。
- 只依赖公开协议；版本固定并在启动时握手。

## 后果

正面：
- 引擎崩溃不影响平台
- 可独立升级、灰度、回退
- 安全边界清晰，权限可按 manifest 收紧
- 多语言实现无障碍

代价：
- 进程启动与 IPC 有开销（用常驻 worker / server 模式缓解）
- 调试跨进程，需要统一事件与日志
- 需要额外的进程监督与僵尸清理

## 替代方案

- **进程内嵌 SDK**：延迟低，但版本与安全风险不可接受，尤其是跑第三方 agent。
- **全部改为远程服务**：更彻底，但首版运维成本高；保留为 M4 演进方向。
