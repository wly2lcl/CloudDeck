# ADR-0005 多租户与计费

- 状态：已接受（D5 见 ADR-0008：订阅 + 额度 + 超量，M3 仅硬上限）
- 日期：2026-11-14

## 背景

产品面向个人与团队，需要数据隔离、配额与成本归集。媒体任务成本高且不可预测，必须在提交与运行两个阶段都受控。

## 决策

- 单库多租户：所有业务表带 `tenant_id`，应用层强制过滤，Postgres RLS 兜底。
- 租户是计费边界；用户可属于多个租户，角色为 owner/admin/editor/viewer。
- 提交时预扣（按 manifest `estimate`），运行时按 driver 上报累加，结束时按实际结算。
- 超配额在提交拒绝；超预算在运行中终止并保留已完成产物。
- `usage_ledger` 是计费唯一事实，按 `tenant + capability + driver + unit` 聚合。

## 后果

正面：
- 隔离与计费口径统一
- 成本可追溯到单 job、单能力、单模型
- 防止单个任务烧穿预算

代价：
- RLS 与分区增加实现与测试成本
- 预扣需要处理多退少补与并发竞争
- 跨租户报表需要额外聚合层

## 替代方案

- **按租户独立数据库**：隔离最强，但运维与迁移成本高，首版不划算。
- **仅应用层过滤**：实现简单，但一次遗漏就是数据事故，不可接受。
