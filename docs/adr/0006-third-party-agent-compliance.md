# ADR-0006 第三方 agent 的接入与合规

- 状态：已接受（分阶段，见 [ADR-0008](0008-commercial-phasing.md)）
- 日期：2026-11-14

## 背景

平台计划通过 Claude Code、OpenCode、dsh 等第三方 agent 执行能力。两条路径的合规含义不同：

1. 平台用自有凭据调用，按任务向用户计费（转售）。
2. 用户在平台配置自己的模型密钥（BYOK），平台仅提供执行环境。

此外还需考虑：CLI 的许可协议、模型 provider 的使用条款、用户数据是否离开平台、agent 产生的代码/内容归属。

## 决策

- 首发仅 BYOK：租户绑定自己的模型凭据，平台不转售模型调用。
- 平台 key 池仅用于内部与试用租户；是否对正式用户开放，由 M3 前的条款核对结论决定。
- 每个 driver 记录「凭据来源」（platform / tenant），计费与审计区分。
- 能力 manifest 增加 `credentials.policy`（`tenant` / `platform` / `either`），首发默认 `tenant`。
- 接入前完成：许可核对、数据流向说明、隐私政策更新、退出机制（可一键切回自研 driver）。

## 待办

- [ ] 核对 Claude Code、OpenCode、dsh 的许可与商用条款
- [ ] 核对各模型 provider 对「代用户调用」的政策
- [ ] 确定数据留存与日志脱敏范围
- [ ] 确定内容与代码的权属声明
- [ ] 准备无第三方 driver 的降级路径（自研 LLM 流水线）

## 决策影响

当前按「不允许转售」保守处理，因此：
- 首发只支持 BYOK
- 平台 key 仅用于内部与评测
- 计费以「平台服务费 + 存储/算力」为主，不按 token 加价

若允许，则保留按量计费，但仍需 BYOK 作为企业选项。

在完成核对前，架构保持双路径，不把任何单一 provider 写死在能力里。
